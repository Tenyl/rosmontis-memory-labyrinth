# 《迷迭香的记忆迷宫》重构设计规格

## 1. 产品定义

《迷迭香的记忆迷宫》是一款以迷迭香为唯一可操控角色的 Web 肉鸽游戏。玩家以“指挥者”身份引导迷迭香穿越非线性记忆迷宫，通过战术指挥、四柄巨剑、资源取舍与记忆碎片构筑完成单局探索，最终稳定记忆核心并逃离迷宫。

游戏必须在没有 API 和网络的情况下完整可玩。LLM 是可选内容扩展，只负责生成受约束的独立事件、小说剧情主题和临时台词；所有拓扑合法性、数值结算、奖励和胜负均由本地规则引擎决定。

## 2. 已批准范围

- 迷迭香是唯一可操控、可养成和持续显示状态的人物。
- 玩家是抽象的指挥者，不建立第二个角色属性面板。
- 记忆投影、残响实体和事件人物可以出现在叙事中，但不进入角色列表、队伍或养成系统。
- 默认模式是离线预设剧情；首次通关后解锁本地无尽模式。
- 配置并启用 LLM 后，可生成受控独立事件、临时台词，并在首次通关后启用小说剧情模式。
- 当前 React、Vite、TypeScript、Zustand、Dexie、Tavern Transport、设计令牌、Dialog、Notification Center、响应式和无障碍基础继续复用。
- 本期不包含其他可玩角色、多人、账号、云同步、付费、实时战斗或后端服务。

## 3. 人物图片资源约束

- 所有语义上属于人物头像、人物半身像或人物立绘的位置，统一渲染项目内空白图片。
- 空白图片的稳定路径为 `/assets/characters/blank-character.svg`。
- 组件不得直接显示角色卡中导入的远程 URL、数据地址或官方角色资源。
- 使用统一 `CharacterArtwork` 组件渲染人物图片，暴露 `avatar`、`portrait` 两种尺寸语义。
- 空白图片保留固定宽高比，防止用户日后替换资源时发生布局偏移。
- 后续用户可以覆盖同一路径的资源文件，或在后续设计批准后扩展资源清单；当前实现不提供角色图片上传或切换 UI。
- 人物图片使用可访问名称；纯装饰场景应传空替代文本并从辅助技术中隐藏。

## 4. 核心游戏循环

单局流程为：

1. 使用 Seed 创建 Run 和合法迷宫拓扑。
2. 从当前节点侦测相邻节点并选择路径。
3. 进入战斗、事件、休整或记忆核心节点。
4. 玩家通过四柄巨剑、事件选项或可识别指挥采取行动。
5. 本地规则结算理智、精神负荷、技能冷却、碎片和节点状态。
6. 记忆碎片溢出时暂停流程，要求保留、遗忘或替换。
7. 收集目标核心碎片并稳定最终记忆核心后逃离。
8. 失败或通关后写入历史 Run；首次通关解锁无尽与小说剧情模式。

## 5. 状态边界

### 5.1 Zustand 战术状态

- `rosmontis`：理智、精神负荷、行动资源、四柄巨剑和临时状态。
- `run`：Run ID、Seed、模式、阶段、回合、层数、当前节点、胜负结果。
- `maze`：节点、边、侦测状态和生成元数据。
- `memoryInventory`：槽位、局内碎片和核心碎片。
- `log`：规则结算与玩家可读事件记录。
- `ui`：选中项、弹层、通知和辅助偏好。

状态使用现有 Zustand persist 基础，增加显式版本和迁移；不引入第二个全局状态框架。

### 5.2 Dexie 与 Tavern Runtime

- Dexie 保存 LLM 设置、固定的迷迭香 Prompt 资料、世界书、生成预设和会话历史。
- Tavern Runtime 继续负责 Prompt 装配、流式传输、停止、超时和解析。
- 角色与 Persona 管理 UI 从游戏界面移除，但固定的迷迭香与指挥者上下文可继续作为内部生成资料。
- LLM 输出先经过运行时验证，再转换为内容草案；不得直接调用 Zustand 数值动作。

## 6. 单主角信息架构

- `/operation`：逐步改造为记忆迷宫主游戏页面。
- `/memory`：保留拓扑与列表等价视图，逐步并入 Run 状态。
- `/operators`：改名为“迷迭香状态”，只显示迷迭香属性、立绘占位、巨剑和碎片摘要。
- `/archive`：后续改造为“记忆图鉴”。
- `/log`：后续改造为 Run 历史与局内规则日志。
- `/settings`：保留视觉、数据和简化后的 LLM 设置。
- 全局酒馆抽屉保留会话、世界书、预设和变量能力；移除角色管理入口。

## 7. 离线肉鸽核心

- 所有随机性来自可注入、可重放的 Seed 随机源。
- 四类节点为残响实体、空白断层、思维温室、记忆核心。
- 节点状态为隐藏、已侦测、可到达、当前位置、已完成、已污染。
- 生成器必须保证起点到记忆核心可达，不产生孤立节点和重复 ID。
- D20、技能、伤害、恢复、碎片与胜负结算实现为无 UI 依赖的纯函数。
- 预设事件由数据配置驱动，文本、触发条件和数值结果分离。
- 离线自由输入只映射到已定义行动；无法识别时返回可恢复提示，不生成伪 AI 内容。

## 8. LLM 扩展

### 8.1 独立事件

LLM 接收经过裁剪的层数、节点类型、理智、精神负荷与碎片摘要，输出标题、情境、2–3 个选项和内容标签。难度、消耗和奖励由本地规则补全。超时、格式错误或校验失败时使用本地事件池。

### 8.2 小说剧情模式

首次通关后解锁。LLM 只生成迷宫主题、章节目标、环境词条、Boss 概念和剧情线索；本地生成器据此创建并校验实际拓扑。关闭 LLM 时使用相同生成器进入本地无尽模式。

### 8.3 临时台词

根据最近事件、玩家指挥和迷迭香状态生成不超过 30 个中文字符的第一人称台词。台词生成不得阻塞规则结算；失败时立即使用本地台词池。

## 9. 视觉、交互与无障碍

- 保留现有深色工业终端令牌与 Phosphor 图标体系。
- 主游戏桌面布局包含状态栏、拓扑、事件/正文、战术行动和碎片摘要；移动端优先事件、选项与核心状态。
- 精神负荷达到 70、85、100 时分别进入警告、危险、失败表达；状态不能只靠颜色区分。
- 故障动效不得覆盖正文或阻断输入，且在 reduced-motion 下完全停用。
- 拓扑提供列表等价视图；所有行动可以使用键盘完成。
- 所有人物图片保留稳定尺寸和 `aspect-ratio`，替换资源时不产生 CLS。
- 所有动态交互控件使用稳定、描述性的唯一 ID。

## 10. 数据迁移

- 当前 `operators.byId` 中仅保留 `rosmontis`；`squadOrder` 过渡为单元素，后续由 `rosmontis` 独立状态替代。
- 当前演示数据中的阿米娅、末药和蛇屠箱从角色、发现者、日志和建议文案中移除。
- 旧持久化数据载入时过滤非迷迭香角色，保留仍可使用的地图、偏好与 Tavern 会话。
- 迁移失败时回退到新的单主角默认状态，不删除 Dexie 中的会话与生成配置。

## 11. 分阶段交付

1. 单主角基础与空白人物资源。
2. 可重放的 Run、迷宫、巨剑与碎片规则。
3. 主游戏界面和离线完整闭环。
4. LLM 独立事件、小说剧情和临时台词。
5. 记忆图鉴、Run 历史、性能和最终 QA。

每个阶段必须独立通过 Vitest、TypeScript、生产构建及相关 Playwright 场景后，才能进入下一阶段。

## 12. 第一阶段完成定义

- 人物头像和立绘统一显示 `/assets/characters/blank-character.svg`。
- 默认战术状态只包含迷迭香。
- “干员与小队”改为“迷迭香状态”，不再显示小队或角色管理标签。
- 主导航和作战概况不再展示其他可玩角色或小队行动序列。
- 酒馆抽屉不再暴露角色管理入口。
- 默认剧情、档案和日志中不包含阿米娅、末药或蛇屠箱。
- 当前全部质量门禁通过，旧数据迁移拥有自动化覆盖。
