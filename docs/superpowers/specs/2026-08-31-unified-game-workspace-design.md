# 《迷迭香的记忆迷宫》一体化游戏工作区重构设计

## 1. 目标

把当前分散在“作战主控台”“意识战场”“迷迭香状态”三个页面中的游玩流程合并为一个连续的游戏工作区。玩家在同一页面查看迷迭香状态、选择迷宫节点、观看进入动画、处理节点遭遇并返回地图，不再通过全局侧边栏和多个路由来回切换。

应用的可见名称统一为“迷迭香的记忆迷宫”。非游玩内容放入顶部菜单；叙事档案、关系图、推理台、战术时间线以及其数据链路全部删除。重构不得改变已经完成的五层规则、八类节点、四柄巨剑、Boss 双阶段、LLM 双轨回退和手记机制。

## 2. 当前基线与问题

- React 19、TypeScript、Zustand、Dexie、React Router、Vitest、Playwright。
- Zustand 持久化版本为 7，存储键为 `rhodes-cognition-terminal-state`；Tavern IndexedDB 版本为 5。
- `AppShell` 使用 264px 左侧导航栏，窄屏缩为图标栏，手机端再转为六项网格导航。
- `/operation` 承载 Run 生命周期、人物状态、战术卡、遭遇、叙事和 Tavern 游戏视图。
- `/memory` 承载当前肉鸽 `maze` 拓扑、节点侦测和移动。
- `/operators` 单独展示迷迭香资料和状态。
- `/archive` 同时承载永久记忆图鉴、迷迭香手记、叙事档案、关系图、推理台和世界书，职责混杂。
- `/log` 同时承载 Run 历史、规则日志、LLM 会话分支和古早战术时间线。
- Store 中存在两套地图：当前肉鸽使用 `maze`；古早 Tavern 投影使用 `memoryMap`。后者及 `MemoryGraph`、`MemoryList`、`MemoryInspector`、`ExpansionDialog` 已不属于当前玩法。
- `archive`、`actionLog`、`memoryMap` 仍被 Tavern 回合投影、演示数据、通知和持久化层写入，不能只隐藏界面。

## 3. 范围与非目标

### 3.1 本次范围

1. 单列应用壳与顶部菜单。
2. 唯一 `/game` 游玩路由。
3. 人物状态、迷宫地图、节点内部和战术操作的一体化工作区。
4. SVG 动态拓扑和场景式节点进入动画。
5. 图鉴、手记、记录、设置的信息架构重排。
6. 古早界面、状态、投影、演示数据和样式清理。
7. Zustand 存档 V7 到 V8 的安全迁移。
8. 桌面、移动、键盘和减少动态效果适配。

### 3.2 非目标

- 不新增角色，主角仍只有迷迭香。
- 不修改战斗数值、节点掉落、五层拓扑规则或第六层以后生成规则。
- 不引入 Canvas、WebGL、Three.js 或新的动画依赖。
- 不删除世界书、角色卡、预设、聊天会话或 API 配置；这些内容只会移动到系统设置。
- 不添加正式立绘、头像、背景、音乐或音效；继续使用 `assets` 注册表中的空白占位资源。
- 不把所有模块同时铺在屏幕上。“一个界面”指同一路由和连续场景，次要内容仍使用渐进披露。

## 4. 新信息架构

### 4.1 顶部菜单

全局侧边栏和侧边栏遥测全部删除。应用采用单列结构：

```text
顶部应用栏
  ├─ 品牌：迷迭香的记忆迷宫
  ├─ 游戏
  ├─ 记忆图鉴
  ├─ 迷迭香手记
  ├─ 行动记录
  ├─ 系统设置
  └─ 当前 Run、连接状态、过载警报、快捷键
主内容
免责声明
```

桌面端显示带文字的水平菜单。空间不足时，优先保留“游戏”和当前状态，其余入口放入顶部“更多”菜单。手机端使用顶部菜单按钮展开下拉层，不使用抽屉式侧边栏或底部六宫格。

顶部菜单的固定可见名称为：游戏、记忆图鉴、迷迭香手记、行动记录、系统设置。不得继续显示“作战主控台”“意识战场”“迷迭香状态”或“罗德岛意识战术终端”。

### 4.2 路由

| 新路由 | 职责 | 旧路由处理 |
| --- | --- | --- |
| `/game` | 唯一游玩工作区 | `/operation`、`/memory`、`/operators` 重定向至此 |
| `/compendium` | 永久记忆图鉴 | `/archive` 重定向至此 |
| `/diary` | 迷迭香手记与博士批注 | 原 `/archive` 手记页签迁入 |
| `/records` | Run 历史与当前局记录 | `/log` 重定向至此 |
| `/settings` | API、预设、世界书、会话、数据、视觉设置 | 保持地址 |

根路由和未知路由重定向至 `/game`。旧路由只提供兼容跳转，不继续懒加载旧页面。

### 4.3 页面标题

- 浏览器 `<title>`：`迷迭香的记忆迷宫`。
- Meta Description：说明这是以迷迭香为主角的纯前端记忆迷宫肉鸽游戏。
- 顶部品牌：`迷迭香的记忆迷宫`。
- `package.json` 包名改为 `rosmontis-memory-labyrinth`。
- 为兼容旧存档，Zustand 存储键本轮保持不变；它是内部迁移标识，不作为可见品牌。

## 5. 唯一游戏工作区

### 5.1 页面结构

`UnifiedGamePage` 是 `/game` 的唯一页面组件，按以下层次组合：

```text
UnifiedGamePage
  ├─ GameHud
  │   ├─ 空白头像占位
  │   ├─ 稳定性、过载、行动点、护盾、共鸣度
  │   ├─ 层数、模式、记忆残响、侦测点
  │   └─ 碎片槽位、认知模块、连接状态
  ├─ RosmontisPresence
  │   ├─ 即时台词
  │   └─ 陪伴交互
  ├─ GameStage
  │   ├─ MazeStage
  │   ├─ NodeTransitionLayer
  │   └─ NodeScene
  ├─ TacticalDeck
  ├─ ContextPanels
  │   ├─ 记忆碎片
  │   ├─ 认知模块
  │   └─ 当前局记录摘要
  └─ RunDialogs
```

`GameHud` 和 `RosmontisPresence` 在地图与节点内部均保持可见。`GameStage` 在地图阶段渲染拓扑，在节点阶段渲染节点内容。战术卡只在当前节点允许对应动作时展开；无关卡片保持收起或禁用，避免把现有所有面板同时堆叠。

桌面端可以在节点内部使用普通响应式内容分栏，但不得形成固定全局导航侧栏。手机端所有节点内容按目标、剧情、动作、结算的顺序纵向排列。

### 5.2 现有组件复用

- `RunStatusBar` 拆分并收敛为 `GameHud`，吸收 `RosmontisProfile` 中当前 Run 真正需要的状态。
- `RosmontisQuotePanel` 和 `CompanionInteractionBar` 合并为 `RosmontisPresence`。
- `RunMazePanel` 拆分为 `MazeStage`、`MazeNode`、`MazeControls` 和无障碍列表。
- `NodeIntelPanel` 的风险和环境信息移入节点预览及节点场景标题。
- `GreatswordActions` 保留规则接口，改为 `TacticalDeck` 的主要内容。
- `EncounterPanel`、`BossEncounter`、`TavernGameView`、`LlmEventDirector`、`ModuleInventory` 和碎片溢出弹窗根据场景整合，不复制规则状态。
- `RunLifecycleDialog` 继续负责新 Run、终局和进入无垠心海，不改规则入口。

## 6. 游戏场景状态机

### 6.1 表现状态

新增只负责界面表现的状态，不把动画状态混入纯规则引擎：

```ts
export type GameScenePhase =
  | 'map'
  | 'entering-node'
  | 'node'
  | 'settling-node'
  | 'returning-map';

export interface GameSceneState {
  phase: GameScenePhase;
  targetNodeId: string | null;
  transitionId: number;
  commitState: 'preview' | 'committed';
  camera: { x: number; y: number; scale: number };
}
```

该状态默认是组件级 Reducer，不进入永久存档。刷新后按规则状态恢复：存在未结算遭遇时进入 `node`；否则进入 `map`。地图视图偏好可以存入 `ui.mazeViewMode`，但不得继续保留旧 `memoryMap` 节点和边。

### 6.2 进入节点

1. 玩家点击可抵达节点。
2. UI 生成新的 `transitionId`，进入 `entering-node`，只锁定冲突的地图移动操作。
3. 0—220ms：节点按压、路径脉冲、镜头开始聚焦；此时 Escape 或“取消”可返回地图。
4. 220ms：若 `transitionId` 仍有效，调用唯一 Store Action `moveToNode(nodeId)`，并把 `commitState` 设为 `committed`。
5. 220—720ms：节点扩张为场景入口，地图层淡出。
6. 规则层创建当前遭遇后，进入 `node`；焦点移动到节点场景标题。

状态提交不得依赖 `animationend`。动画被取消、浏览器降帧或标签页失焦时，Reducer 仍必须落在合法终态。提交后不允许取消规则移动，但顶部菜单、辅助功能和紧急关闭仍可使用。

点击隐藏、污染、封锁或尚不可抵达的节点不得移动，只显示明确原因。点击当前且存在未结算遭遇的节点直接打开节点场景。

### 6.3 结算与返回

节点完成后先进入 `settling-node`，展示奖励、碎片、状态变化和下一步。玩家选择“返回迷宫”后进入 `returning-map`；退出动画为进入动画的约 60% 时长。完成后恢复地图镜头、原节点焦点和可抵达路径。

标准进入动画为 650—850ms；减少动态效果模式改为最长 120ms 的交叉淡入淡出，规则提交时序保持一致。

## 7. 动态 SVG 迷宫

### 7.1 图层

`MazeStage` 使用单个 SVG 和 HTML 节点覆盖层：

1. 深色神经网格和低频漂移背景。
2. 已完成、可抵达、封锁和未知路径。
3. 节点按钮。
4. 当前节点扫描环、可抵达呼吸、Boss 锁定环。
5. 过载噪声和色散覆盖层。
6. 相机容器，统一应用平移与缩放。

连线根据拓扑生成曲线路径，不再使用固定直线。布局继续按深度分列，但每列通过节点数量、相邻边和最小间距计算纵向位置；同一拓扑和视口应产生稳定布局。

### 7.2 操作

- 指针拖动平移，滚轮或显式按钮缩放。
- 提供“当前节点”“适应全图”“放大”“缩小”按钮。
- 键盘使用方向键在可见节点间移动焦点，Enter 进入节点。
- 保留“节点列表”作为等价操作路径；列表与地图共享同一 `maze.nodes`。
- 交互不依赖 Hover；Hover 只补充风险和环境预览。
- 节点点击目标至少 44×44px，节点状态同时使用形状、描边和文字，不只用颜色。

### 7.3 节点主题动效

- 常规作战：锐利切割与敌情锁定。
- 紧急作战：高频警报与短促信号撕裂。
- 安全屋：噪声消退与信号稳定。
- 认知黑市：横向终端扫描。
- 奇境：轻微折射与记忆波纹。
- 命运抉择：路径分裂后停驻在两个选择锚点。
- 未知：遮蔽剥离和真实类型揭示。
- 领袖之敌：封锁环闭合和阶段警告。

持续动画最多同时强调当前节点和一个待进入节点。动效只使用 `transform`、`opacity`、SVG 描边和合成层滤镜，避免改变布局尺寸。

## 8. 节点内部场景

所有节点共用 `NodeSceneShell`，固定顺序为：节点身份、目标、叙事、可用动作、即时结果、最终结算。

- 常规作战与紧急作战：四柄巨剑战术卡是主要操作，不保留重复纯文本攻击按钮。
- 安全屋：恢复、安抚、资源整理和离开。
- 认知黑市：购买、出售、模块管理和离开。
- 奇境：本地或 LLM 情境、选项、D20 阈值和结果。
- 命运抉择：明确列出代价、收益和确认步骤。
- 未知：在进入动画中揭示真实节点类型，然后复用真实类型场景。
- 领袖之敌：沿用守门 Boss 和“封闭之心”双阶段规则；非法动作展示迷迭香第一人称原因。

节点未结算时，“返回迷宫”保持禁用并解释原因。节点结算后显示奖励、稳定性、过载、碎片和模块变化；不会让玩家自行对照多个页面寻找结果。

## 9. 图鉴、手记、记录与设置

### 9.1 记忆图鉴

`CompendiumPage` 只读取 `memoryCompendium`，展示情感碎片、痛苦碎片、技能碎片和核心记忆的永久发现记录。删除叙事档案、关系图、推理台和世界书页签。

### 9.2 迷迭香手记

`DiaryPage` 复用 `DiaryPanel`，保留本地与 LLM 手记、博士批注和 IndexedDB 持久化。图鉴与手记使用独立顶部菜单入口，不再嵌套在多功能档案页中。

### 9.3 行动记录

`RecordsPage` 只展示：

- `runHistory`：每次成功、失败、层数、回合、节点和最终状态。
- `ruleLog`：当前 Run 的移动、检定、巨剑、安抚、奖励和结算事件。

规则日志必须格式化为普通玩家可读的标题和状态变化；原始 JSON 只允许在开发环境的折叠诊断区显示。删除战术时间线、筛选器、回溯弹窗和 `actionLog`。LLM 会话分支不属于游戏记录，移动到系统设置的会话管理页。

### 9.4 系统设置

现有接口连接、生成预设、解析协议、本地数据、视觉辅助继续保留，并新增两个设置工作区：

- 内容资料：世界书、角色卡和玩家身份。
- 会话管理：聊天会话与会话分支。

现有顶部“酒馆编排”大按钮取消；顶部只显示简洁连接状态，点击后进入系统设置的对应页签。

## 10. 古早模块清理

### 10.1 删除的界面与资源

- `MemoryPage`、`OperatorsPage`、旧 `ArchivePage`、旧 `LogPage`。
- `MemoryGraph`、`MemoryList`、`MemoryInspector`、`ExpansionDialog`。
- `ArchiveFilters`、`ArchiveGrid`、`ArchiveDialog`、`ArchiveRelationGraph`、`ReasoningBoard`。
- `ActionTimeline`、`ReplayDialog`。
- 只服务于上述组件的样式、测试、唯一 ID 和响应式规则。

`RosmontisProfile` 中可复用的状态展示先迁入 `GameHud`，再删除独立页面；不能因为删页面而丢失玩家仍需要的稳定性、过载、巨剑和碎片信息。

### 10.2 删除的状态与投影

- `ArchiveRecord`、`ArchiveLink`、`ArchiveState` 及所有档案 Store Action。
- `ActionLogEntry`、`actionLog`、相关选择器和 Tavern 来源回溯。
- 古早 `memoryMap.nodes`、`memoryMap.edges`、选择节点、扩展节点及其 Store Action。
- Tavern 投影中的 `memory.node.discovered`、`archive.clue.discovered`、`archive.npc.discovered` 和对应变量读取。
- 档案未读计数、档案通知、深层病历奖励和旧行动日志写入。

当前肉鸽 `maze`、`ruleLog`、`runHistory`、`memoryCompendium` 和 `diary` 是保留的数据来源。LLM 生成新迷宫继续通过已验证的 `llmDirector` 和 `mindsea-floor-v1`，不得回退到古早 `memoryMap` 投影。

### 10.3 删除的演示内容

清除 `demoData`、默认角色卡、默认预设、通知和测试中的旧故事残留，包括：护理员伊莲、R-09、凌晨 03:17、异常雨幕病历、失温病历、潮湿病历、深层合唱以及旧终端名称。

五层当前正式主题和当前规则测试使用的内容不因字符串相似而机械删除；只有不再被五层设计引用的古早档案叙事需要移除。清理后执行源码扫描，禁止旧模块名称重新出现在运行时界面。

## 11. 存档迁移

Zustand 持久化版本从 7 升至 8。

### 11.1 V7 到 V8

- 删除 `archive` 和 `actionLog`。
- 删除古早 `memoryMap` 节点、边、选中节点和扩展状态。
- 如果旧 `memoryMap.viewMode` 合法，将它迁移为 `ui.mazeViewMode`；否则使用 `graph`。
- 保留 `run`、`maze`、`rosmontis`、`memoryInventory`、`economy`、`modules`、`explorationCharges`、`routeEffects`、`pendingEncounter`、`progression`、`runHistory`、`ruleLog`、`memoryCompendium`、`llmDirector`、`session`、`operators.rosmontis` 和界面偏好。
- 旧存档中存在未结算遭遇时，新界面首次恢复到节点内部；否则恢复到地图。

### 11.2 IndexedDB

Tavern IndexedDB V5 不改版本。角色卡、玩家身份、世界书、预设、设置、会话、消息和手记原样保留。移动入口不能触发删除或重建数据库。

### 11.3 重置与备份

- 重置说明删除档案、关系图和战术时间线文案。
- Tavern 备份格式保持兼容，不包含已删除的 Zustand 古早字段。
- API 密钥继续不进入备份。

## 12. 错误处理与恢复

- 非法节点点击只产生角色化提示，不改变 Run。
- 动画中出现组件卸载、路由变化或新 transition 时，旧 `transitionId` 立即失效。
- Store 移动失败时回到地图、恢复目标节点焦点并显示具体原因。
- 远程内容失败继续使用现有本地回退，不中断节点进入或规则结算。
- 页面刷新后从权威 Run 状态派生场景，不持久化半完成动画。
- 顶部菜单离开未结算节点时保留 Run；返回“游戏”必须恢复同一节点场景。

## 13. 响应式、无障碍与性能

- 断点继续采用 375、768、1024、1440 的系统化范围。
- 桌面端移除侧栏后，主舞台最大宽度扩展至可用视口；长篇叙事仍限制为 60—75 个字符宽度。
- 手机端使用 `min-height: 100dvh`，避免固定栏遮挡内容，不产生横向页面滚动。
- 所有节点、菜单、卡片、缩放和返回按钮具有描述性 ID、可见焦点和至少 44×44px 点击区域。
- 路由变化后焦点进入主标题；节点进入后焦点进入节点标题；返回地图后焦点回到当前节点。
- 无障碍节点列表可完成侦测、进入和查看状态的全部操作。
- `prefers-reduced-motion` 和应用“减少动效”同时生效，停用漂移、抖动、缩放和持续呼吸。
- 动画每帧主线程工作目标低于 16ms；地图相机只写一个 CSS Transform，指针移动使用 `requestAnimationFrame` 合批。
- 过载动效不能遮挡文字或导致正常文本对比度低于 4.5:1。

## 14. 测试策略

所有功能改动遵循测试先行。

### 14.1 单元测试

- 场景 Reducer 的合法转换、取消、提交、过期 transition 和恢复规则。
- SVG 节点布局的稳定性、最小间距和同种子确定性。
- V7 到 V8 迁移只删除古早字段并保留当前 Run。
- 规则事件到玩家可读记录的格式化。

### 14.2 组件测试

- 不渲染全局侧边栏，顶部菜单包含五个固定入口。
- 品牌和页面标题均为“迷迭香的记忆迷宫”。
- `GameHud`、地图、台词和陪伴交互位于同一游戏页面。
- 点击可抵达节点执行一次移动；不可抵达节点不移动。
- 减少动态效果时场景仍完成切换。
- 图鉴没有叙事档案、关系图和推理台；记录没有战术时间线。
- 设置可以访问世界书、角色卡和会话管理。
- 所有交互 ID 唯一，键盘焦点顺序与视觉顺序一致。

### 14.3 端到端测试

- 从 `/game` 启动离线 Run，进入至少一种普通节点并返回地图。
- 覆盖八类节点的地图进入和节点场景装载。
- 第五层 Boss 双阶段仍能完成。
- 旧 `/operation`、`/memory`、`/operators`、`/archive`、`/log` 正确重定向。
- 刷新未结算节点后恢复同一节点场景。
- 375px、768px、桌面视口和减少动态效果环境无横向溢出、无侧栏、无控制台错误。

### 14.4 源码契约

生产代码和演示数据不得包含：叙事档案、情报关系图、证据推理台、战术时间线、罗德岛意识战术终端。用于证明旧内容已被移除的测试可以保留这些断言字符串；旧路由兼容测试也可以保留旧路径字符串，但不得渲染旧页面。

最终运行完整 Vitest、TypeScript 类型检查、Vite 构建和 Playwright。地图性能通过浏览器性能采样确认没有持续布局抖动。
