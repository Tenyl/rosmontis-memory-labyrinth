# 罗德岛意识战术终端 SillyTavern 全面整合设计

## 1. 设计目标

在不引入后端服务的前提下，将现有“罗德岛意识战术终端”从本地演示型 TRPG 原型升级为完整的 SillyTavern 前端游戏运行时。改造后，玩家能够配置 OpenAI 兼容接口、选择角色与玩家身份、管理世界书和预设、创建多个会话、进行流式剧情交互、回滚或分支历史，并让 LLM 输出持续驱动干员状态、意识战场、情报档案和行动记录。

现有六个核心页面、中文化内容、冷峻医疗/军事终端美学、响应式布局和无障碍能力必须保留。SillyTavern 能力应成为产品的数据与交互内核，而不是附加在现有界面上的独立工具箱。

## 2. 已批准的安装选项

- 启用游戏模式，默认界面为“正文 + 战术选项 + 自由指令”。
- 使用默认六标签：`maintext`、`option`、`sum`、`vars`、`thinking`、`think`。
- 次 API 默认关闭，但保留完整配置界面，用户可主动启用变量/总结分流。
- 本期不启用 schema-first 状态系统。
- 默认提供无 API 凭据也能运行的本地模拟适配器；配置远程接口后切换到真实流式生成。
- API 密钥只保存在当前浏览器 IndexedDB，不进入日志、导出包或界面明文摘要。

## 3. 方案选择

### 3.1 采用：酒馆内核与战术领域桥接

将 SillyTavern v3 React 模板中的数据库、世界书引擎、提示词装配、导入导出、变量解析、流解析与 API 路由作为独立内核放入 `src/sillytavern/`。在其上建立一个 React 运行时 Provider，统一向界面暴露会话、角色、预设、世界书、变量、生成状态和操作方法。

现有 Zustand 游戏状态继续负责视觉化战术领域：迷迭香状态、意识节点、情报记录、行动日志和通知。新增的领域桥接层把每轮解析后的结构化输出投影到 Zustand，使所有现有页面响应同一轮 LLM 交互。

该方案避免两套互不相干的聊天系统，也避免为了引入 IndexedDB 而重写所有成熟页面。

### 3.2 未采用：直接叠加技能模板

直接复制模板组件最省时，但会形成独立聊天弹窗、独立变量面板和独立设置系统，视觉与状态都和现有终端割裂，不符合“全面酒馆化”。

### 3.3 未采用：以 Dexie 完全替换 Zustand

完全以数据库记录驱动六个页面能够统一持久化，但需要重写现有状态选择器与大量已验证交互。对纯前端单人游戏而言复杂度与迁移风险高于收益。

## 4. 总体架构

```text
玩家操作
  ↓
战术游戏视图 / 会话控制
  ↓
TavernRuntime Provider
  ├─ 会话、角色、玩家身份、世界书、预设管理
  ├─ PromptAssembler + LorebookEngine
  ├─ ApiRouter（主 API / 可选次 API / 本地模拟）
  ├─ StreamParser（六标签增量解析）
  └─ Dexie 数据库（持久化）
  ↓
TurnProjector 领域桥接
  ├─ 正文与摘要 → 剧情流、行动记录
  ├─ vars → 干员与任务状态
  ├─ 新节点 → 意识战场
  └─ 线索/NPC → 情报档案库
  ↓
Zustand 战术视图状态
```

### 4.1 边界原则

- `src/sillytavern/` 只包含与产品视觉无关的纯领域逻辑、存储和外部格式适配。
- `src/features/tavern/` 包含罗德岛风格的酒馆管理界面与运行时 Provider。
- `src/features/operation/` 消费运行时接口，不直接访问 Dexie 或拼装 API 请求。
- `src/store/` 只接收已经验证的战术领域事件，不解析 LLM 原始文本。
- 远程 API 是可替换端口；本地模拟器实现同一个流式接口，确保原型始终可体验。

## 5. 数据模型与持久化

Dexie 数据库采用版本化 schema，至少包含以下表：

- `settings`：UI 模式、六标签、主/次 API、活跃角色、玩家身份、活跃预设和活跃世界书。
- `characters`：SillyTavern V2 兼容角色卡字段、头像数据 URL、绑定世界书、创建与更新时间。
- `personas`：玩家显示名、描述、头像和默认变量。
- `lorebooks`：世界书元数据及完整条目集合。
- `presets`：采样参数、提示词块和 `prompt_order`。
- `chats`：会话元数据、消息、每轮变量快照、父分支信息和更新时间。

现有 Zustand 持久化继续保存展示偏好和战术投影。启动时，Tavern Provider 先完成 Dexie 初始化和默认数据播种，再恢复最后活跃会话。数据库迁移失败时不覆盖旧数据，而是进入可恢复的错误状态并提供 JSON 备份入口。

### 5.1 默认内容

- 默认角色卡：迷迭香，包含角色描述、性格、场景、首条消息和对话示例。
- 默认玩家身份：博士。
- 默认世界书：罗德岛行动协议、迷迭香认知档案、切尔诺伯格残响。
- 默认预设：认知战术叙事，内置中文六标签输出协议与战术状态更新约束。
- 默认会话：雨幕回声，与当前演示剧情衔接。

默认内容均为可编辑、可导出数据，而不是写死在组件中的展示文案。

## 6. Prompt 与世界书流程

每次发送按以下顺序构建请求：

1. 校验当前角色、玩家身份、预设和会话。
2. 将玩家输入、最近历史、角色描述和变量组成扫描上下文。
3. 运行世界书递归扫描，支持主关键词、次关键词、选择逻辑、常驻条目、概率、顺序和递归限制。
4. 按预设 `prompt_order` 装配系统提示词、角色信息、世界书、示例、历史和当前输入。
5. 将当前变量块和六标签格式协议注入系统提示词。
6. 交给 API Router；主 API 负责正文，启用次 API 时可处理总结或变量任务。
7. 使用 AbortController 支持停止；失败后保留玩家消息并允许重试。

宏至少支持 `{{user}}`、`{{char}}`、`{{original}}` 与 `{{变量名}}`。上下文长度按预设限制裁剪历史，但不删除数据库中的消息。

## 7. 流式解析与回合投影

流解析器必须处理标签跨 chunk、多个选项、未闭合标签、纯文本回退和尾部残片。界面在生成过程中分别显示：

- `maintext`：主要剧情正文，逐段流入叙事面板。
- `option`：生成完一个完整选项后追加到战术选择区。
- `thinking` / `think`：默认折叠，仅展示“战术推演进行中”状态与可展开内容。
- `sum`：作为行动记录摘要和会话列表摘要。
- `vars`：解析为暂存变量，整轮验证通过后一次性合并。

回合结束后，`TurnProjector` 将变量与结构化标记转换为领域事件。例如：

- `rosmontis_stress`、`sanity` 更新干员指标。
- `memory_node_*` 新建或更新意识战场节点。
- `clue_*` 与 `npc_*` 建立情报档案。
- `risk`、`objective`、`squad_status` 更新战术概况。

无法识别的变量仍保留在会话变量面板中，不得静默丢失；非法数值不能覆盖有效旧值。

## 8. 页面与交互改造

### 8.1 全局终端框架

- 顶栏新增模型连接状态、当前角色、当前预设和会话切换入口。
- 侧栏维持六个一级目的地，不新增同层级导航，避免信息架构膨胀。
- 全局提供“酒馆编排”抽屉，集中访问角色卡、玩家身份、世界书、预设、会话和变量。
- 所有模态框具备唯一描述性 ID、焦点圈定、Esc 关闭、关闭按钮和返回焦点。
- 通知全部使用内部通知中心，不调用浏览器 `alert`、`confirm` 或外部 toast。

### 8.2 作战主控台

- 将现有本地叙事流升级为 Tavern GameView，但保留三栏战术工作台语义。
- 中央正文区显示角色发言、叙述、检定、触发世界书数量和生成状态。
- 输入区支持自由指令、六标签生成状态、停止、继续、重试与重新生成。
- 战术选项使用键盘数字键和显式按钮选择，选中后填入输入框而非立即提交。
- 历史抽屉支持从任意消息回滚、编辑玩家消息重新生成、删除后续、建立分支。
- 右侧战术概况增加本轮变量变化与触发条目，不暴露完整系统提示词或 API 密钥。

### 8.3 意识战场

- 节点继续支持向下、向左、向右拓建。
- LLM 新建节点时显示来源回合与变量证据；用户可跳转回对应历史消息。
- 角色/世界书切换不会删除既有节点；不同会话拥有独立战术投影。

### 8.4 干员与小队

- “干员档案”与“角色卡管理”合并，迷迭香是默认活跃角色。
- 支持新建、编辑、复制、删除、导入和导出 SillyTavern V2 JSON 角色卡。
- 玩家身份以独立 Persona 管理，避免把玩家描述写入角色卡。
- 小队状态继续显示战术数值；来自 LLM 的变化标明回合来源。

### 8.5 情报档案库

- 增加“跑团档案”和“世界书”两个工作区，并保留关系图与推理板。
- 世界书支持批量 JSON 导入、导出、启停、编辑条目和关键词命中预览。
- NPC 与线索由回合投影自动创建时进入待复核状态，玩家可编辑或固定。
- 关系图可显示档案、角色、世界书条目和来源回合之间的关系。

### 8.6 行动记录

- 将日志时间线升级为会话与分支树。
- 每个节点显示角色、预设、世界书快照、变量差异、消息数量和父分支。
- 支持加载会话、重命名、分支、删除和 JSON 导出；删除必须使用内部确认框。

### 8.7 系统设置

- 拆分为“接口连接”“生成预设”“解析协议”“本地数据”“视觉与辅助”标签页。
- 主 API 支持 Base URL、API Key、模型、超时和流式开关；提供显式连接测试。
- 次 API 使用独立配置组，默认关闭。
- 预设编辑器支持采样参数、系统提示词、自定义 prompts 与顺序调整。
- 数据管理支持完整备份、恢复、清理聊天和恢复默认内容。
- API 密钥字段支持显示/隐藏，不参与通用备份导出。

## 9. 视觉与体验规范

- 沿用黑、白、高级灰、迷迭香浅蓝和法术荧光绿，所有新颜色通过语义令牌声明。
- 新界面采用高密度战术仪表盘布局，信息密度高但正文行长限制在 75 个字符以内。
- 使用现有 Phosphor 图标体系，禁止 emoji 作为结构图标。
- 所有主要点击目标在触控布局中至少 44×44 CSS px，状态不能只靠颜色表达。
- 动效只使用 `transform` 和 `opacity`，用于抽屉来源、流式状态、条目触发和选择确认。
- 遵循 `prefers-reduced-motion`；快速状态切换可中断且不依赖动画结束维护正确性。
- 375、768、1024、1440 宽度下无横向页面溢出；移动端优先展示正文与输入，次要面板折叠为抽屉。
- 表单使用永久可见标签、字段级错误、辅助文案和保存反馈，不能仅依赖 placeholder。
- 路由跳转后聚焦主内容，弹窗关闭后返回触发器。

## 10. 错误处理与安全边界

- 未配置 API：明确显示本地模拟模式，并提供前往设置的操作。
- 连接失败：显示原因、HTTP 状态或超时类型，允许重试和切回本地模拟。
- 流中断：保留已接收正文并把消息标记为中断，不合并未验证的 vars。
- 导入失败：逐文件报告，成功文件照常导入；不因单个坏文件回滚全部结果。
- 存储不可用：进入只读演示模式，显示持久化不可用的内部通知。
- 删除会话、角色、世界书或本地数据库必须二次确认，并说明影响范围。
- 代码中不得包含真实 API 密钥、远程代理、服务器路由或数据库后端。

## 11. 性能策略

- 新管理页和大型编辑器按路由或弹窗动态导入。
- Dexie 查询按活跃实体加载；会话列表不一次渲染完整消息正文。
- 超过 50 条的消息或条目列表使用窗口化或分页。
- 流式 chunk 先在解析器缓冲，再按动画帧批量提交 React 状态，避免每个 token 重渲染整页。
- 选择器保持细粒度；Tavern Provider 将动作和状态分离，减少上下文级联刷新。
- 不引入 GSAP 等仅用于装饰的重型依赖。

## 12. 测试与验收

### 12.1 单元测试

- 世界书主/次关键词、选择逻辑、常驻、递归、概率边界。
- Prompt 顺序、宏替换、历史裁剪和变量注入。
- 流解析的跨 chunk、多选项、未闭合标签和纯文本回退。
- vars 提取、类型转换、非法值保护和领域事件投影。
- 角色卡、世界书、预设和完整备份的导入导出。
- 会话创建、编辑重生成、删除后续、分支和变量快照。

### 12.2 组件与集成测试

- 首次初始化播种并恢复活跃会话。
- 设置、世界书、预设、角色卡、会话和变量界面可完成核心 CRUD。
- 本地模拟与远程流式适配器共享同一 UI 状态机。
- 每个新交互元素 ID 唯一，弹窗焦点与键盘路径完整。
- 领域投影能更新六个页面，而非只更新聊天正文。

### 12.3 E2E 与视觉验收

- 从新会话创建、选择角色和世界书、提交行动，到查看节点/档案/日志的完整流程。
- 编辑旧消息重新生成、删除后续和创建分支。
- 导入/导出世界书、角色卡、预设和完整备份。
- 375、768、1024、1440 宽度以及 reduced-motion 模式。
- 无浏览器原生警告框、无 emoji 结构图标、无控制台错误、无横向溢出。
- TypeScript、Vitest、Vite build 和 Playwright 全部通过。

## 13. 完成定义

只有当以下条件全部由当前代码和运行结果证明时，改造才算完成：

1. `dexie` 已安装，技能要求的 React 酒馆内核文件存在并通过测试。
2. 设置、角色、玩家身份、世界书、预设、会话和变量均有完整中文前端管理界面。
3. 主操作台真实使用 Prompt 装配、世界书扫描、API Router 和流解析器。
4. 消息、变量与选择在刷新后由 IndexedDB 恢复。
5. 回滚、编辑重生成、删除后续和分支会话均可运行。
6. LLM 回合能够驱动干员、意识节点、档案和行动日志的跨页更新。
7. 未配置 API 时仍能通过本地模拟完整体验，不伪装成远程连接。
8. 所有新界面符合现有视觉系统、中文化、无障碍、响应式与性能约束。
9. 全量自动化验证及浏览器人工验收通过。
10. 设计、计划、实现和验证提交均已推送到 GitHub `main`。
