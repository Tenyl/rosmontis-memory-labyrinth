# 《迷迭香的记忆迷宫》B+C 初版验收记录

日期：2026-08-30

工作分支：`codex/rosemary-memory-maze`

仓库：`Tenyl/rosmontis-memory-labyrinth`

环境：Windows / Node.js v24.14.0 / pnpm 11.19.0 / Chromium（Playwright 1.62.1）

## 验收结论

项目已形成以迷迭香为唯一主角、无需 API 即可完成的三层前端肉鸽初版。每层迷宫由可复现种子生成，包含战斗、休息处、商店、奇境、未知与最终 Boss 房；路线、数值、奖励、模块、碎片、过载和胜负均由本地规则引擎负责。可选 LLM 只补充独立事件、临时台词和小说模式叙事，不能改变本地拓扑或结算。

所有未来图片与音频入口统一登记在 `src/assets/assetRegistry.ts`。项目根目录 `assets/` 提供人物、节点和模块的中性 SVG 占位图，以及待替换的图片、BGM、音效目录；未提供的音频保持 `null`，不会产生失效网络请求。

## 浏览器与视觉检查

Playwright 在 1440×900、1024×768、768×1024 和 375×812 生成并检查 `/operation`、`/memory`、`/operators`、`/archive`、`/log`、`/settings` 及酒馆编排联络表。检查结果：

- 页面根节点不存在水平滚动；移动端地图默认使用单列战术列表。
- 作战状态、资源统计与遭遇面板在窄屏按单列排列，没有裁切主操作按钮。
- 地图节点以图标和文字共同标识，未知节点在侦测前不暴露内部结果。
- 当前遭遇未结算时，“进入节点”会禁用并明确提示返回作战主控台，不再静默拒绝。
- 人物与模块占位图加载完整；尚无音频时界面显示“声音资源待填充”。
- 二级世界书/预设编辑器保持逐项分行，未回退此前已修复的堆叠问题。

## 静态与安全审计

- 运行时源码未发现 `TODO`、Lorem Ipsum、`Math.random()` 或 `console.log/debug/info/warn/error`。
- 游戏随机流程全部使用可复现种子；旧存档迁移到版本 5，并保留局外图鉴和通关进度。
- 远程小说节点必须逐项匹配本地 `nodeId` 与公开 `nodeType`；`hiddenType` 不会写入 Prompt 输出结构。
- API Key 保存在浏览器侧接口设置中，不写入游戏 localStorage、规则日志或叙事摘要。
- 项目仍为纯前端直连，正式远程端点必须允许 CORS；浏览器中的 API Key 不具备服务端密钥隔离能力。
- `assets/audio/` 当前仅为资源槽位，不会播放伪造或临时音频；替换资源后只需修改注册表。

## 后续资源填充说明

正式资源按 `assets/README.md` 的目录约定放置。图片推荐 WebP，音频推荐 Ogg；在 `src/assets/assetRegistry.ts` 中替换对应导入即可，不需要改动业务组件。原 `public/assets/characters/blank-character.svg` 已移除，避免出现两套人物占位资源来源。
